## 0. WHAT THIS IS

A personal site that behaves like a CAD viewport. It began life as a literal cream-paper broadsheet
newspaper ("The Irregular" — columns, briefs, pull-quotes, a morgue for killed drafts). The Field
Edition keeps that newspaper SOUL — dense dispatches, notice panels, a morgue — but renders it as a
dark computational-design environment: near-black ground, one acid-green accent, mono chrome, object
snapping, a command line, a WebGL globe of real flights.

Owner: **Prajwal** — architect / computational designer (Dar · Sidara, Dubai), aviation enthusiast, DJ.
Voice in all copy: dry, precise, self-aware; posts read like field reports.

**Non-negotiables**
1. **Dark only.** There is no light mode (it was built and deliberately removed — do not reintroduce).
   The dark palette IS the identity.
2. Vanilla only. No framework, no jQuery, no Tailwind. Sole runtime deps: three.js + globe.gl (CDN).
3. Single-page output: one `index.html`. Reader & lightbox are overlays; navigation is hash-based.
4. Every module degrades gracefully: offline, no-WebGL, reduced-motion, touch/mobile.
5. **All content comes from Markdown + one config file.** Zero personal copy hardcoded in templates —
   set the site the way you'd set a newspaper: write the copy, the press lays it out.

## 2. DESIGN TOKENS (dark, exact — do not "improve")

```css
:root{
  --bg:#0a0b0d;  --bg2:#0f1114;  --fg:#e9ebe6;
  --ink:233,235,230;        /* neutral triplet → rgba(var(--ink),a) for all greys */
  --acc-rgb:204,255,0;      /* accent triplet → rgba(var(--acc-rgb),a) for glows/borders */
  --dim:rgba(var(--ink),.72);
  --faint:rgba(var(--ink),.42);
  --line:rgba(var(--ink),.1);
  --acc:#ccff00;            /* acid — text/marks */
  --acc-dim:rgba(var(--acc-rgb),.12);
  --grid:rgba(var(--ink),.1);
  --card:rgba(15,17,20,.5);
  --panel-bg:rgba(15,17,20,.85);
  --overlay-bg:rgba(10,11,13,.92);
  --mono:'JetBrains Mono',monospace;   /* 300/400/500 */
  --disp:'Space Grotesk',sans-serif;   /* 300/400/500/700 */
}
```

The `--ink` / `--acc-rgb` triplet indirection is deliberate architecture — keep it even though there's
one theme. Status colors: live/active `--acc`; warn/paused `#e8a33d`; info/shipped `#57b0ff`;
danger `#ff5c57`; osnap markers pure `#fff`. Fixed CAD grid: `body::before`, 110px cells of `--line`,
radial mask, pans with cursor (`--gpx/--gpy`, factor .018) + scroll (.05), opacity .3. Reveal: `.rv`→`.in`
via IntersectionObserver (rootMargin -6%, .65s, stagger 50ms×(i%6)); all motion gated by `prefers-reduced-motion`.

### Type = two buckets (this was decided deliberately — honor it)
- **CONTENT — legible.** Anything a visitor READS: reader prose (.92rem), CV blurb (.85), story
  excerpts (.82), brief text (.8), experiment/spec descriptions (.8), titles (.9–1.6rem). Floor ≈ .7rem.
  Never shrink these for density.
- **CHROME — codified, tight.** Labels/tags/kickers/coords/index-numbers/nav/command-line — all
  mono + UPPERCASE + letter-spaced. These live small (.44–.6rem) on purpose; they read as instrument
  readouts, not text. Do NOT inflate them to a uniform accessible size — the mono-upper-tracked
  treatment is the signal that a string belongs to this bucket.

### 3.1 Wiring config into templates and the browser

Eleventy reads config via `_data/`; the browser gets a minimal slice injected at build time so
client JS never hardcodes coordinates or usernames:

```js
// src/_data/config.js  → available as `config` in every template
module.exports = require('../../field.config.js');
```

```njk
{# In the page template, before the main <script> — the browser's config slice #}
<script>
window.__FIELD = {
  github:   { username:"{{ config.identity.github }}" },
  weather:  { lat:{{ config.based.lat }}, lon:{{ config.based.lon }}, tz:"Asia/Dubai", cacheTTL:3600000 },
  based:    { label:"{{ config.based.label }}", lat:{{ config.based.lat }}, lon:{{ config.based.lon }} }
};
</script>
```
All live-data JS (§9) reads `window.__FIELD` — never literals. Changing `based` in config moves the
weather, the wind fetch, the visitor-distance anchor, and the globe home in one edit.

### 3.2 Config-driven design tokens (do NOT hardcode the palette in field.css)

The dark tokens (§2) are emitted from config by an Eleventy shortcode into a `<style>` block in
`<head>`, exactly like the newspaper build. This keeps the palette single-sourced — an accent tweak
is a config edit, never a stylesheet hunt. Add the token values to config and generate:

```js
// field.config.js → add:
tokens:{ bg:'#0a0b0d', bg2:'#0f1114', fg:'#e9ebe6',
         ink:'233,235,230', accRgb:'204,255,0', acc:'#ccff00',
         card:'rgba(15,17,20,.5)', panelBg:'rgba(15,17,20,.85)', overlayBg:'rgba(10,11,13,.92)' },
```
```js
// .eleventy.js → shortcode writing the :root block from config.tokens
eleventyConfig.addShortcode('fieldTokens', () => {
  const t = require('./field.config.js').tokens;
  return `<style>:root{--bg:${t.bg};--bg2:${t.bg2};--fg:${t.fg};--ink:${t.ink};`
    + `--acc-rgb:${t.accRgb};--dim:rgba(var(--ink),.72);--faint:rgba(var(--ink),.42);`
    + `--line:rgba(var(--ink),.1);--acc:${t.acc};--acc-dim:rgba(var(--acc-rgb),.12);`
    + `--grid:rgba(var(--ink),.1);--card:${t.card};--panel-bg:${t.panelBg};`
    + `--overlay-bg:${t.overlayBg};--mono:'JetBrains Mono',monospace;--disp:'Space Grotesk',sans-serif}</style>`;
});
```
`field.css` then contains only the derived rules (`.dim{color:var(--dim)}` …), never raw hex. There
is only ONE theme — do not emit a `body.dark` variant (the newspaper had two; the Field is dark-only).

## 8. INTERACTION (the CAD soul — highest fidelity; port, don't reinvent)

All desktop-only bits gate on `FINE_PTR = matchMedia('(hover:hover) and (pointer:fine)')` and respect
`REDUCED = prefers-reduced-motion`.

- **8.1 Cursor + crosshair.** `cursor:none`; acid 5px dot (instant) · ring 32px lerp .16 (→56px+label
  from `data-cursor` on hover; vocab READ DEVELOP EXHUME GO TOP TYPE PULL ROUTE BASE MAIL FEED SPEC) ·
  mono `X Y` coords (mirrored in status bar) · 4-segment crosshair with 9px center gap, edge-fading ·
  12px pickbox.
- **8.2 Osnap End/Mid/Near.** Registry rebuilt on `snapDirty` (scroll/resize/1s/`transitionend` of
  `.rv` — the transitionend hook fixes the reveal-offset bug; exclude `.rv:not(.in)` and `.dim`).
  Snappables: `.story .brief .quote .panel .lead .exp-row .ph .mg-entry #map-wrap .masthead-name
  .cv-block .spec-card`. Priority End(≤13)→Mid(≤13)→Near(≤9, project onto segment). Marker: white
  square/triangle/diamond + status `OSNAP: END ◉`.
- **8.3 Construction lines.** Hover snappable → 4 dashed acid lines to viewport edges, `z-index:120`
  (above sticky topbar). Hide on leave/scroll.
- **8.5 (no particle field.** Removed — the CAD grid carries the ambience. Do not add it back.)
- **8.6 Boot gate — ONCE EVER (localStorage `fieldbooted`).** Rhino-history lines staggered 260ms:
  `_Open "theirregular.3dm"` · `File loaded: 32 objects, 5 layers, 1 viewport.` · `_Osnap End=On …` ·
  `_ZoomExtents position {based}` · `_Print press online_` · then blinking
  `▸ PRESS ENTER TO ENTER THE FIELD_` waiting on Enter/click/touch → sets flag, masthead scrambles in.
  **No fortune line, no auto-typed help** (both removed). 12s / any-error force-dismiss so the overlay
  never traps clicks. `boot` command clears the flag + reloads.
- **8.7 WIRE quote.** Generated `.quote` injected at flow ~pos 6: `// QUOTED · WIRE`, text, attr,
  `PULL ↻`. `pullWire()`: dummyjson random → `AUTHOR · WIRE`; any fail → baked 5-quote archive
  (Rams/Gall/Saarinen/Eames/Johnson) `· ARCHIVE`. Never empty.
- **8.8 Scramble & tilt.** Glyph-noise decode on masthead post-boot and travel-feed titles per render.
  **Flow/story titles do NOT scramble on hover** (removed as over-eager). Panel tilt per §7.
- **8.9 Command line — ALWAYS pinned above status bar.** `/` focuses, Esc blurs, ↑/↓ history, Tab
  completes, live hint. Outputs `.c-in/.c-ok/.c-err/.c-res` (clickable).
  **Registry (19 total — trimmed on purpose; do NOT re-bloat):**
  `help` · `open <n>` · `search <term>` (posts+morgue, clickable; briefs/quotes as info) ·

### 9.1 Caching discipline (adopt for every fetch)

Every live fetch caches to `localStorage` with a TTL so the site doesn't hammer APIs or rate-limit
GitHub on repeat visits. Pattern (from the newspaper build, keep it):

```js
async function cached(key, ttl, fetcher){
  try{
    const hit = JSON.parse(localStorage.getItem(key) || 'null');
    if (hit && Date.now() - hit.ts < ttl) return hit.data;
  }catch{}
  const data = await fetcher();
  try{ localStorage.setItem(key, JSON.stringify({ ts:Date.now(), data })); }catch{}
  return data;
}
```
- **Weather** (topbar temp): Open-Meteo, `window.__FIELD.weather`, TTL 1h, key `field_wx`. Map WMO
  codes → short label. On any error, leave `—°C` (never throw into the UI).
- **GitHub activity** (CV block): `/users/{u}` + `/users/{u}/events/public?per_page=100`, TTL 1h, key
  `field_gh_{u}`. Derive 7-day bars, streak, 30-day commit count, followers, repos. Honest empty
  states (`QUIET WEEK` / `NO PUSHES`) — never a bare 0.
- **WIRE quote / METAR / ipapi**: no cache needed (WIRE is intentionally fresh per pull; METAR is
  on-demand; ipapi is once per load). All wrapped so failure is silent + falls back.

NOTE: This project does NOT use localStorage for UI state inside artifacts, but the *deployed* site
(plain web page, not an artifact) may use it freely for these caches. The once-ever boot flag
(`fieldbooted`) also lives in localStorage.

## 14. SEO (first-class — the prototype has none; build it in)

The prototype is a single anonymous page. The deployed site must be properly indexable and shareable.
Every generated page (home + each standalone post, §15) gets the full set, resolved in the template
from `config.site` / `config.social` / the post's frontmatter.

### 14.1 Meta / Open Graph / Twitter (component `head-seo.njk`)
```njk
<title>{% if pageTitle != site.title %}{{ pageTitle }} — {{ site.title }}{% else %}{{ site.title }}{% endif %}</title>
<meta name="description" content="{{ pageDesc }}">
<link rel="canonical" href="{{ pageUrl }}">
{% if noIndex %}<meta name="robots" content="noindex, nofollow">{% else %}<meta name="robots" content="index, follow">{% endif %}
<meta property="og:type" content="{{ pageType | default('website') }}">
<meta property="og:title" content="{{ pageTitle }}">
<meta property="og:description" content="{{ pageDesc }}">
<meta property="og:url" content="{{ pageUrl }}">
<meta property="og:image" content="{{ pageImage | default(config.seo.ogImage) }}">
<meta property="og:image:width" content="1200"><meta property="og:image:height" content="630">
<meta property="og:site_name" content="{{ site.title }}">
<meta name="twitter:card" content="{{ config.seo.twitterCard }}">
<meta name="twitter:title" content="{{ pageTitle }}">
<meta name="twitter:description" content="{{ pageDesc }}">
<meta name="twitter:image" content="{{ pageImage | default(config.seo.ogImage) }}">
```

### 14.2 JSON-LD
- **Home** → `@graph` of `WebSite` + `Person` (name, url, `sameAs` = the config.social links,
  jobTitle "Architect & Computational Designer", address from `based`).
- **Each standalone post** (posts, not briefs/quotes/morgue) → `BlogPosting`
  (`Article` for long ones): headline, description (frontmatter `excerpt`), datePublished/Modified,
  author+publisher = the `Person` @id, `articleSection` = tag, `image` if the post has one.
- Use `| dump | safe` for any string interpolated into JSON-LD so quotes/newlines escape correctly.

### 14.3 sitemap / robots / headings
- `sitemap.njk → /sitemap.xml`: all indexable pages; **exclude morgue**; priority lead 0.9 /
  longform 0.8 / story 0.7.
- `robots.njk → /robots.txt`: `Allow: /`, `Disallow: /assets/`, `Sitemap: {config.site.url}/sitemap.xml`.
- **Headings:** exactly one `<h1>` per page (the masthead publication name on home; the post title on
  a standalone post page). Section heads are `<h2>`. Never skip a level. The reader overlay's title is
  the page `<h1>` only on the standalone route, not inside the inline overlay.
- **Morgue is `noindex, nofollow`** automatically (killed drafts shouldn't rank).

## 15. STANDALONE POST PAGES + SHAREABLE URLS

The single-page field is the experience, but each post also needs a real, canonical URL for sharing
and SEO. Two layers:

1. **Static route** — every post also builds at `/posts/[slug]/` via posts directory data:
   ```njk
   {# content/posts/posts.njk — applied to all post .md #}
   ---
   permalink: "posts/{{ page.fileSlug }}/"
   layout: layouts/post.njk        # minimal dark page: masthead + the article + back-to-field link
   ---
   ```
   `layouts/post.njk` renders the same dark shell with just that one article (full SEO, JSON-LD,
   canonical). This is what crawlers and link-unfurlers hit.
2. **Inline overlay + pushState** — on the field page, opening a post in the reader overlay already
   writes `#open=NUM`. Upgrade it to also `history.pushState` the canonical `/posts/{slug}/` URL so the
   address bar shows a shareable link; closing restores the field URL. `popstate` re-syncs the overlay.
   Keep the existing hash deep-links working as a fallback.

## 16. .eleventy.js (collections, filters, token + markdown wiring)

```js
const cfg = require('./field.config.js');
module.exports = function(ec){
  ec.addPassthroughCopy('src/assets');

  // Collections from content/
  ec.addCollection('posts',  c => c.getFilteredByGlob('src/content/posts/*.md')
      .filter(p => p.data.layout !== 'morgue').sort((a,b)=>b.date-a.date));
  ec.addCollection('travel', c => c.getFilteredByGlob('src/content/posts/*.md')
      .filter(p => p.data.tag === 'travel').sort((a,b)=>b.date-a.date));   // → Travel feed
  ec.addCollection('morgue', c => c.getFilteredByGlob('src/content/morgue/*.md')
      .sort((a,b)=>b.date-a.date));

  // Filters
  ec.addFilter('isoDate', d => new Date(d).toISOString().split('T')[0]);
  ec.addFilter('num3',    n => String(n).padStart(3,'0'));
  ec.addFilter('dump',    v => JSON.stringify(v));
  ec.addFilter('absUrl',  p => `${cfg.site.url}${p}`);

  // Config-driven tokens (§3.2) — emits the :root <style> block
  ec.addShortcode('fieldTokens', () => { /* see §3.2 */ });

  // Serialize collections → window.DATA constants for the client bundle (00-data.js)
  // POSTS/BRIEFS/QUOTES/MORGUE/PHOTOS/FLOW shapes MUST match the prototype exactly.

  ec.setServerOptions({ port:3000, watch:['src/assets/**','field.config.js'] });
  return { dir:{ input:'src', output:'dist', includes:'_includes', data:'_data' },
           htmlTemplateEngine:'njk', markdownTemplateEngine:'njk' };
};
```
No `{redact}` markdown plugin — that was a newspaper mechanic and isn't part of the Field build.
Markdown bodies become the `body:[...paragraphs]` arrays the reader expects (split on blank lines).
